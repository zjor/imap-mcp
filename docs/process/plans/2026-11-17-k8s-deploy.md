# Kubernetes Deployment and CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy imap-mcp to the operator's cluster with a Helm chart, and deploy every release tag from GitHub Actions, with no site-specific values in git.

**Architecture:** A Helm chart in `deploy/chart/` renders a Deployment, Service and Ingress. The image is the one goreleaser already pushes (`ghcr.io/zjor/imap-mcp:<version>`). A `deploy` job in `.github/workflows/ci.yml` runs after `release` (or by hand), writes the k8s Secret from GitHub secrets and runs `helm upgrade --install --atomic`. Manual fallback scripts and a runbook live next to the chart.

**Tech Stack:** Helm 3, ingress-nginx, cert-manager, GitHub Actions, bash.

**Spec:** `docs/process/specs/2026-11-17-k8s-deploy-design.md`

## Global Constraints

- Release `imap-mcp`, namespace `imap-mcp`, Secret `imap-mcp-secrets`, kube context `midgard` (scripts only, overridable with `KUBE_CONTEXT`).
- Image `ghcr.io/zjor/imap-mcp`, tag = version without `v` (goreleaser `{{ .Version }}`).
- No domain, IMAP host or token in any committed file. Examples use `mail-mcp.example.com` and `imap.example.com:993` only in comments and docs.
- Ingress: class `nginx`, cluster issuer `letsencrypt-prod`, `proxy-body-size: 30m`, `proxy-buffering: "off"`, `proxy-request-buffering: "off"`, `proxy-read-timeout: "600"`, `proxy-send-timeout: "600"`.
- Pod security: `runAsNonRoot`, uid/gid 65532, `readOnlyRootFilesystem: true`, drop `ALL`, `allowPrivilegeEscalation: false`, seccomp `RuntimeDefault`.
- GitHub secrets live in environment `production`: `KUBECONFIG`, `INGRESS_HOST`, `IMAP_MCP_IMAP_HOSTS`, `IMAP_MCP_ACCESS_TOKENS`.
- Pin third-party GitHub actions by commit SHA with a version comment, as `ci.yml` already does.

**Builder call (deviation from spec, minor):** `values.yaml` leaves `ingress.host` and `image.tag` empty, and the templates use `required`. Then a deploy without a host or tag fails, and it never goes out with a placeholder host. The example host appears in comments only.

## Review Focus

1. `INGRESS_HOST` set with a scheme or a trailing slash (`https://x/`): the deploy must fail early with a clear message, not create a broken Ingress. Test in Task 3.
2. Manual deploy with `version: v0.1.0` (with the `v`): strip it, so the tag `0.1.0` is used. Test in Task 3.
3. An empty GitHub secret: the deploy must fail before it touches the cluster and name the missing secret. Test in Task 3.
4. The host must not appear in the workflow log: mask it before any command prints it. Test in Task 3 (actionlint plus a read of the step order).
5. A render without `ingress.host` or `image.tag`: `helm template` fails with the `required` message. Test in Task 1.

### Task 3: Deploy job in GitHub Actions

**Files:**
- Modify: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: chart (Task 1), Secret name and keys (Task 2), the `release` job.

- [ ] **Step 1: Add the trigger and the job**

- Add `workflow_dispatch` with a required string input `version`.
- The `ci` and `release` jobs keep their behavior. `release` must not run on `workflow_dispatch`; its current `if` already ensures this.
- New job `deploy`:
  - `needs: [ci, release]`. On dispatch, `release` is skipped, so use `if: always() && needs.ci.result == 'success' && (needs.release.result == 'success' || github.event_name == 'workflow_dispatch')`.
  - `environment: production`, `concurrency: {group: deploy-production, cancel-in-progress: false}`, `permissions: contents: read`.

Steps in this order:
1. checkout;
2. **Validate inputs:**
   - Fail with `missing secret <NAME>` when any of the four secrets is empty. Pass them through `env:`, never inline `${{ secrets.* }}` in `run:`.
   - Run `echo "::add-mask::$INGRESS_HOST"`.
   - Fail when the host contains `/` or `:`.
   - Compute `tag`: on a tag push, `${GITHUB_REF_NAME#v}`; on dispatch, `${VERSION#v}`. Check it against `^[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$`.
3. **Write kubeconfig** to `$RUNNER_TEMP/kubeconfig` with mode 600, as in accounting's `ci.yml`.
4. **Apply Secret:** `kubectl -n imap-mcp create secret generic imap-mcp-secrets --from-literal=IMAP_MCP_IMAP_HOSTS="$IMAP_MCP_IMAP_HOSTS" --from-literal=IMAP_MCP_ACCESS_TOKENS="$IMAP_MCP_ACCESS_TOKENS" --dry-run=client -o yaml | kubectl apply -f -`.
5. **Helm upgrade:** `helm upgrade --install imap-mcp deploy/chart --namespace imap-mcp --set image.tag="$TAG" --set ingress.host="$INGRESS_HOST" --atomic --timeout 5m`.
6. **Verify:**
   - The Deployment image equals `ghcr.io/zjor/imap-mcp:$TAG`.
   - `curl -fsS https://$INGRESS_HOST/healthz` returns `ok`. Retry 12 times, 5 s apart, because the certificate may need time on the first deploy.

Between steps 5 and 6, run `kubectl -n imap-mcp rollout restart deployment/imap-mcp` and `kubectl -n imap-mcp rollout status deployment/imap-mcp --timeout 2m`. Helm rolls the pods only when the rendered chart changes, so a token change in the Secret alone needs this restart.
